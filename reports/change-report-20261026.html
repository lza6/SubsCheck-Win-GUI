1. 上下文（为什么做）

终局审计发现三项 P0：① PATH 上的 Framework MSBuild（csc 仅 C#5）无法编译项目使用的 C#7 语法（22+ 处 CS1056），且快速启动脚本命中它后变量为空必然失败；② WebUI API 密钥硬编码公开可猜值 CMLiussss；③ 程序用按钮文字（button1.Text）作运行状态判据，托盘/定时器与按钮状态耦合易竞态。另有 P1：空 catch 吞异常、64 位机永远下载 32 位内核。

2. 关键决策与取舍（直觉）

  • 凭据加密方案的撤回：最初按安全指南对 github-token/worker-token/webdav-password 做 DPAPI 加密（GUI 侧 15 项断言全过）。独立审查发现 config.yaml 是与外部 subs-check.exe 内核的共享契约文件——凭据字段由 Go 内核直接读取执行上传，加密会导致上传功能静默损坏。果断撤回（22ed3b3）。教训：GUI 侧测试全绿 ≠ 跨进程链路真实可用。
  • bat 脚本走 VS MSBuild：不做 csproj 工具链升级（违反"禁止大幅重构"），仅改脚本探测顺序规避。
  • 状态机最小化：只做枚举 + 收口属性，不引入事件/接口抽象。

7. 测验（自测，满分 100）

Q1（选择）为什么撤回了凭据 DPAPI 加密？
A. DPAPI 性能差 B. config.yaml 由外部 subs-check.exe 内核读取，内核不解密文 C. 加密算法有 bug D. 用户反对

答案B（config.yaml 是跨进程共享契约文件，凭据字段由 Go 内核消费）

Q2（判断）PATH 上的 Framework MSBuild 加 /p:LangVersion=latest 就能编译本项目。（×）

答案错。其 csc 编译器本身只支持到 C#5，报 CS1617；必须用 VS MSBuild。

Q3（简答）随机密钥弹窗为什么区分 githubProxyCheck 参数？

答案SaveConfig(false) 是自动路径（内核更新/订阅保存/开机自启），modal 弹窗会阻塞无头/托盘场景的启动流程；仅手动启动路径（true）弹窗，自动路径记日志。

Q4（判断）WebUIapiKey 初值改 null 后必须同步赋值路径，否则 timer4 轮询 X-API-Key 传 null 抛异常。（√）

答案对，修复方式是 ReadConfig 读取 api-key 时同步赋值。

Q5（简答）回滚本批变更的最小单元是什么？

答案每个 commit 独立 revert；如撤密钥改动 revert 密钥相关 commit 即可，config 读取兼容旧值无数据迁移。
