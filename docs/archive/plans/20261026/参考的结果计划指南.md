## Decisions and Assumptions
- 已确认事实：主项目是内核外挂式 GUI，可靠性瓶颈在进程管理与输出解析，而非网络能力
- 假设 A1：用户希望保持 .NET Framework 4.7.2 与免安装便携形态（影响能否引入测试框架与依赖体积），**待用户确认**
- 决策 D1：不采用 Electron/Tauri 重写、不引入 Web 服务端；仅在 P2 作为产品扩展选项
- 决策 D2：改造以「先抽纯逻辑 → 建测试 → 再拆窗体」顺序推进，避免在无测试下动核心链路
- 决策 D3：参考项目只迁移设计思想，不复制代码；跨栈项目（Go/Rust/Python）只取模块边界与交互流程
- 否决方案：整体重写（成本不可控、丢失上游同步能力）、直接引入第三方代理池/内核替代 subs-check（超出授权与兼容边界）
